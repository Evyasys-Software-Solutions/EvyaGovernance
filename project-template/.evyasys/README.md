# `.evyasys/` — Your project's Evyasys workspace

This folder lives **inside your project's git repo** alongside `src/`, `docs/`, etc.  
Everything here is yours to read, edit, and commit. Nothing is hidden from you.

## What you can freely edit

| Path | What it controls | Notes |
|------|-----------------|-------|
| `project.yaml` | PM tool, notification tool, branding, velocity | Re-run `/evyasys:Setup` or edit directly |
| `docs/*.md` | Quality-gate documents | Re-run `/evyasys:CreateDocs --retrain` after architecture changes |
| `memory/glossary.json` | Business terms used in story drafting | Free-form JSON `{ "term": "definition" }` |
| `memory/decisions.md` | Past decisions that constrain future work | Markdown, append freely |
| `memory/modules.md` | Module/component knowledge for better story scoping | Markdown, append freely |
| `rules/definition-of-ready.md` | DoR checklist for CreateStory and FinishDev | Overrides plugin default |
| `rules/naming.md` | Story ID prefix, branch naming, PR naming conventions | Overrides plugin default |
| `workflows/<name>/PROMPT.md` | Agent instructions for any command | Project file always wins over plugin default |
| `workflows/<name>/AGENT.md` | Persona/role definition for any command | Project file always wins over plugin default |
| `inputs/` | Drop any doc here — CreateStory reads it automatically | No naming convention required |
| `board/**/*.md` | Any story artefact | Safe to edit — just markdown files |
| `board/referencedoc/**` | Archived reference docs with analysis | Edit or add notes freely |

## How to override a workflow prompt

To change how any command behaves for your project (without touching the plugin):

1. Create the file at `.evyasys/workflows/<command-name>/PROMPT.md`
2. Write your override — the project file wins over the plugin default.

Available command names: `setup`, `create-docs`, `create-story`, `create-subtask`,  
`start-dev`, `review-dev`, `finish-dev`, `start-qa`, `finish-qa`, `generate-release-note`

Example: add a custom AC format requirement to CreateStory:
```
# Project override: CreateStory
# Extends the plugin default — add project-specific constraints here.

All acceptance criteria must follow the format:
  GIVEN [precondition]
  WHEN  [action]
  THEN  [expected outcome]

...rest of story requirements...
```

## How to add custom business knowledge

Drop files into `inputs/` and they are automatically loaded by every command:
- Requirements docs, PO briefs, stakeholder emails
- Architecture decision records
- API specs, data dictionaries
- Wireframes (paste as markdown/text — images not supported yet)

These are read at session start and injected into every agent's context.

## The referencedoc archive

When you use `/evyasys:CreateStory` and choose **"Reference document"**, the agent:
1. Reads your source doc
2. Adds a BA + Architect analysis section
3. Appends all clarifying Q&A
4. Saves the enriched file to `.evyasys/board/referencedoc/{YYYY-MM-DD}/{filename}`

This archive is yours — commit it, browse it, add notes to it. It's the traceability chain from "what was asked for" to "what was built". When the team asks "why was this feature designed this way?", the answer is in `referencedoc/`.

## project.yaml quick reference

```yaml
name: "Your Project"          # Shows in notification cards

story:
  id_prefix: "EVYA"           # Prefix for story IDs (EVYA-1042)
  velocity: 20                # Team velocity (SP per sprint) — used for SP estimation
  point_scale: "3,5,8,13,21"  # Fibonacci scale for story points

pm_tool: "devops"             # local | devops | jira | github

azure_devops:                 # Required if pm_tool: devops
  org: "YourOrg"
  project: "YourProject"

notification_tool: "teams"    # none | teams | slack | whatsapp | email

teams:
  webhook: ""                 # Teams incoming webhook URL

release_notes:                # Optional — for GenerateReleaseNote
  company_name: "Acme Corp"
  logo_path: "assets/logo.png"
  brand_color: "#0078d4"
  output_dir: ".evyasys/releases/"
  naming_convention: "v{version}"
```

Run `/evyasys:Setup` to configure interactively at any time.
