# Quality Gates

## Story creation gate

A story can be shown to the user only if:
- the business purpose is clear
- the workflow is understandable
- roles are identified
- prerequisites are complete
- acceptance criteria are testable
- dependencies are explicit
- out-of-scope is explicit
- assumptions are visible
- open questions are listed
- repo impact has been reviewed
- technical implementation details are excluded
- **Impacted Areas domain flags are set** (Security / DB / Frontend / API / Performance)

A story can be pushed only if:
- user confirms
- the draft passed self-review
- the board mapping is known
- epic linkage is resolved or intentionally skipped

## Quality-gate documents system (`.evyasys/docs/`)

The project maintains 20 living quality-gate documents in `.evyasys/docs/`.
These are generated by `/evyasys:TrainDocs` and must be kept current by the architect gate
in ReviewDev and FinishDev.

Every workflow loads documents based on the story's **Impacted Areas** domain flags:

| Doc | Always loaded | Loaded when flag is set |
|---|---|---|
| `ARCHITECTURE.md` | StartDev, ReviewDev, FinishDev | — |
| `RULES.md` | StartDev, ReviewDev, FinishDev | — |
| `STANDARDS.md` | StartDev, ReviewDev, FinishDev | — |
| `PATTERNS.md` | StartDev, ReviewDev, FinishDev | — |
| `ERROR_HANDLING.md` | StartDev, ReviewDev, FinishDev | — |
| `TESTING.md` | StartQA | — |
| `SECURITY.md` | — | Security flag |
| `DB_STANDARDS.md` | — | DB flag |
| `FRONTEND.md` | — | Frontend flag |
| `DESIGN_SYSTEM.md` | — | Frontend flag |
| `UI_UX_STANDARDS.md` | — | Frontend flag |
| `API_STANDARDS.md` | — | API flag |
| `PERFORMANCE.md` | — | Performance flag |

### When to regenerate docs

Run `/evyasys:TrainDocs --retrain` after any PR that:
- introduces a new architectural pattern
- adds or changes an API contract
- changes auth or permission model
- adds a DB migration
- changes a hot path or response time characteristic
- changes frontend component structure or design tokens

The architect gate table in ReviewDev and FinishDev tracks this obligation per PR.

## Dev gate (FinishDev)

A branch can move to Ready for QA only if:
- every AC has an identifiable automated test
- all CHECKLIST.md items pass
- Dev Summary is complete with "Docs to update" table filled
- architect gate resolved or deferred with documented justification

## QA gate (FinishQA)

A story can move to Done only if:
- no P0 or P1 defects are open
- every AC is signed off by Product Owner
- all domain-specific test gates pass (Security / Performance / Accessibility / Data Integrity)
- release notes are written in plain user-facing language
- roll-back plan is documented or explicitly N/A
