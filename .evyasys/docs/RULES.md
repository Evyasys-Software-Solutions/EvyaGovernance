# Rules

> Generated by /evyasys:TrainDocs on 2026-06-17. Violations block merge.

Every rule uses "must" or "never". No ambiguity.

---

## Plugin structure rules

1. Every command **must** have a `skills/evyasys-{command}/SKILL.md` and a `skills/evyasys-{command}/hooks.js`. A command without both files is incomplete and must not be shipped.

2. Every `hooks.js` **must** be registered in `.ai/commands.yaml` under the `commands:` key with `trigger`, `skill`, `agent`, `prompt`, and `checklist` fields before the command is usable.

3. Every new command's PROMPT.md **must** include at least one explicit human confirmation gate (`ctx.confirm(...)` in hooks.js) before any file is written to disk or any PM tool call is made.

---

## Local-first rule

4. Every `hooks.js` **must** save artefact files locally (`fs.writeFileSync`) before attempting PM tool sync. PM sync failure **must never** prevent the local file from being created. This is the local-first guarantee.

---

## External call rules

5. **Never** call `node-fetch` directly from `hooks.js`. All HTTP calls **must** go through `runIntegration()` in `scripts/lib/dryrun.js` so dry-run mode intercepts them transparently.

6. **Never** call PM tool APIs directly from `hooks.js`. All PM operations (createEpic, createStory, setState, createBug) **must** route through `scripts/lib/pm-adapter.js`.

7. **Never** call notification APIs directly from `hooks.js`. All notifications **must** route through `scripts/lib/notify-adapter.js`.

8. Every integration adapter **must** implement the same function signature as the other adapters for the same operation so `pm-adapter.js` can route to it without special-casing.

---

## Credentials and secrets rules

9. **Never** store secrets (PATs, API tokens, SMTP passwords, Twilio credentials) in `project.yaml`, `.env` files committed to git, or any file that travels with the project repository.

10. All secrets **must** be stored encrypted in `~/.evyasys/credentials` using `scripts/lib/encrypt.js` (`encrypt()` / `decrypt()`). The file **must** be written with mode `0o600`.

11. The machine-bound encryption key is derived as `sha256("evyasys:{hostname}:{username}")`. This means credentials are not portable across machines by design. Any new credential added to the system **must** use `writeUserCreds()` from `scripts/lib/config.js` — **never** write to the credentials file directly.

---

## Output block rules

12. Every command that produces artefacts **must** embed them in the canonical delimited block format:
    - Story content: `=== EVYA_STORY: {id} ===` ... `=== END_EVYA_STORY: {id} ===`
    - Epic content: `=== EVYA_EPIC: {id} ===` ... `=== END_EVYA_EPIC: {id} ===`
    - Batch manifest: `<!-- EVYABATCH { json } -->`
    Hooks **must** use `parseDelimitedBlocks()` and `parseBatchBlock()` to parse these — **never** ad-hoc regex.

---

## Config rules

13. Config resolution **must** follow this order: `process.env` → `~/.evyasys/credentials` → `.evyasys/project.yaml` → plugin manifest defaults. **Never** read from these sources directly in a hook — always call `loadConfig()` from `scripts/lib/config.js`.

14. Every new configurable value **must** be added to `scripts/lib/config.js:loadConfig()` return object, to `.env.example` (with a comment), and to `project-template/.evyasys/.env.example` if it is project-level. **Never** hardcode a default value inline in a hook.

---

## AI prompt rules

15. Every PROMPT.md **must** define explicit numbered steps. Steps that trigger irreversible actions (file creation, PM sync, notifications) **must** be preceded by a gate step marked `⛔` that waits for user confirmation before proceeding.

16. Business story content **must** remain free of technical implementation details (no class names, endpoints, DB schema, framework specifics). Technical analysis belongs in `_TechBrainstorm.md`, not in `_UserStory.md`.

---

## Code quality rules

17. A single `hooks.js` file **must** not exceed 300 lines. If it grows beyond this, extract parsers, formatters, and notification helpers into `scripts/lib/` modules.

18. **Never** use synchronous `readline` prompts in `hooks.js`. The interactive prompt helper (`prompt()`) in `config.js` guards for non-TTY environments — always use it, never `process.stdin.read()` directly.
