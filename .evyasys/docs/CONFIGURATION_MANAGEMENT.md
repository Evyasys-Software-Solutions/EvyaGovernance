# Configuration Management

> Generated by /evyasys:TrainDocs on 2026-06-17.

## Configuration Hierarchy

Config values are resolved in this priority order (highest wins):

```
1. process.env          — CI/CD environment variables or manual shell exports
2. ~/.evyasys/credentials  — per-user encrypted secrets (AES-256-CBC, never committed)
3. .evyasys/project.yaml   — per-project non-sensitive config (committed to git)
4. .ai/manifest.yaml defaults — plugin-level fallback defaults
```

Implemented in `scripts/lib/config.js:loadConfig()`. All hooks must call `loadConfig()` — never read `process.env` directly.

## Per-Environment Differences

| Setting | Local dev | CI / staging | Production |
|---|---|---|---|
| `EVYASYS_DRY_RUN` | `0` (live, developer controls it) | `1` (preview — no accidental board writes from CI) | `0` |
| `AZURE_PAT` | From `~/.evyasys/credentials` | From CI secret store (e.g. GitHub Actions secret) | Same as CI |
| `TEAMS_WEBHOOK` | From `project.yaml` (committed) | Same | Same |
| PM tool | `devops` or developer's choice | `local` recommended for CI (no PM writes from automated runs) | `devops` |

## Secrets Management

### Storage
- All credentials (PAT, API tokens, SMTP password) are stored encrypted in `~/.evyasys/credentials`.
- File format: `KEY=<ivHex>:<ciphertextHex>` (one per line).
- File permissions: `0o600` — enforced by `scripts/lib/config.js:writeUserCreds()`.
- Encryption: AES-256-CBC with a machine-bound key derived as `sha256("evyasys:{hostname}:{username}")`.
- Credentials are machine-bound and unreadable if the file is copied to another machine.

### Access
- Only the current OS user can read `~/.evyasys/credentials` (mode 0o600).
- The `loadConfig()` function reads and decrypts all credentials at hook startup.
- The decrypted values are available in the `cfg` object in memory for the duration of the hook only.

### Rotation procedure
1. Run `scripts/login.sh` (macOS/Linux) or `scripts/setup.ps1` (Windows) to re-enter credentials.
2. Or run `/evyasys:Setup` in Claude Code — the Setup wizard validates credentials live before saving.
3. New encrypted values overwrite the old entry in `~/.evyasys/credentials`.
4. All running hooks must be restarted to pick up new credentials.

### Leaked credential procedure
1. Immediately revoke the compromised PAT/token in the PM tool's admin console.
2. Generate a new PAT/token with the minimum required scope.
3. Run `/evyasys:Setup` to store the new credential.
4. Audit recent PM tool activity logs to assess exposure scope.

### What must NOT be in git
- `~/.evyasys/credentials` — never committed anywhere
- `.evyasys/.env` — never committed (local secret override file)
- Any file containing a bare PAT, API token, SMTP password, or Twilio auth token

## project.yaml Quick Reference

Location: `{project}/.evyasys/project.yaml` — committed to the project's git repository.

```yaml
name: "Customer Portal"          # Shows in notification cards
story:
  id_prefix: "EVYA"              # Story ID prefix — all teams should use same prefix
  velocity: 20                   # Story points per sprint (for SP estimation)
  point_scale: "3,5,8,13,21"    # Fibonacci scale available for estimation

pm_tool: "devops"                # local | devops | jira | github
azure_devops:
  org: "EvyaCorp"
  project: "CustomerPortal"
work_item_types:
  epic: "Epic"                   # Override for Scrum/CMMI process templates
  story: "User Story"
  task: "Task"

notification_tool: "teams"       # none | teams | slack | whatsapp | email
teams:
  webhook: ""                    # Channel webhook — safe to commit (not a personal token)
```

## Config Validation on Startup

`loadConfig()` does not throw on missing values — it returns empty strings. Hooks validate required values before making external calls:

```js
if (!cfg.azure.org || !cfg.azure.project) {
  throw new Error('AZURE_ORG / AZURE_PROJECT not set (check .evyasys/project.yaml or env).');
}
if (!cfg.azure.pat) {
  throw new Error('No PAT available. Run scripts/login.sh or scripts/setup.ps1 once.');
}
```

**Gap**: There is no startup validation that checks all required variables for the configured pm_tool before any command runs. This should be added to the session-start hook to surface configuration errors early.

| `project.yaml` | `{project}/.evyasys/project.yaml` | PM tool, notification, project identity, story config |

| `.env.example` | project root | Documents all env var overrides for CI use |
