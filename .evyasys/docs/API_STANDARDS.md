# API Standards

> Generated by /evyasys:TrainDocs on 2026-06-17.

This project consumes external APIs — it does not expose one. These standards govern how the integration adapter layer calls PM tool and notification APIs.

---

## Azure DevOps REST API

**Base URL**: `https://dev.azure.com/{org}/{project}/_apis/wit/`
**API version**: `7.1` (appended as `?api-version=7.1`)
**Authentication**: HTTP Basic with empty username and PAT as password — `Authorization: Basic {Base64(":{pat}")}`
**Content-Type for writes**: `application/json-patch+json` (ADO uses JSON Patch for work item mutations)
**Accept**: `application/json`

Implemented in `scripts/integrations/azure_devops.js:adoFetch()`.

### Work item creation payload format

ADO uses JSON Patch operations to set fields:
```json
[
  { "op": "add", "path": "/fields/System.Title", "value": "Story title" },
  { "op": "add", "path": "/fields/System.Description", "value": "<html content>" },
  { "op": "add", "path": "/fields/System.WorkItemType", "value": "User Story" }
]
```

Story markdown is converted to HTML before posting via `scripts/lib/markdown-to-html.js`.

### Error handling
- HTTP non-2xx responses throw: `ADO {METHOD} {url} failed: {status} {body}`
- Missing config throws before any HTTP call: `AZURE_ORG / AZURE_PROJECT not set`
- Missing PAT throws: `No PAT available. Run scripts/login.sh or scripts/setup.ps1 once.`

## JIRA REST API

**Authentication**: HTTP Basic with email + API token — `Authorization: Basic {Base64("{email}:{apiToken}")}`
**Base URL**: `https://{domain}/rest/api/3/`
**Content-Type**: `application/json`

Implemented in `scripts/integrations/jira.js`.

---

## GitHub Projects GraphQL API

**Authentication**: `Authorization: Bearer {token}`
**Endpoint**: `https://api.github.com/graphql`
**Content-Type**: `application/json`

Implemented in `scripts/integrations/github_board.js`.

---

## Microsoft Teams Incoming Webhook

**Protocol**: HTTP POST to channel webhook URL
**Content-Type**: `application/json`
**Payload format**: Adaptive Card or simple message card JSON

Implemented in `scripts/integrations/teams_webhook.js`.

---

## Slack Incoming Webhook

**Protocol**: HTTP POST to webhook URL
**Content-Type**: `application/json`
**Payload format**: Slack Block Kit JSON or simple `{ text: "..." }`

Implemented in `scripts/integrations/slack_webhook.js`.

---

## Twilio WhatsApp API

**Authentication**: HTTP Basic with Account SID + Auth Token
**Endpoint**: `https://api.twilio.com/2010-04-01/Accounts/{accountSid}/Messages.json`
**Content-Type**: `application/x-www-form-urlencoded`

Implemented in `scripts/integrations/whatsapp.js`.

---

## SMTP (Email)

**Protocol**: SMTP via nodemailer (lazily installed)
**Port**: 587 (default, configurable via `EMAIL_SMTP_PORT`)
**TLS**: STARTTLS on port 587
**Auth**: SMTP username + password

Implemented in `scripts/integrations/email.js`.

## Adapter Contract Rules

All integration adapters must follow these rules to be routable by `pm-adapter.js` and `notify-adapter.js`:

1. All exported functions must be `async`.
2. On success: return an object with at least `{ id }` for create operations, or truthy for state/notification operations.
3. On failure: throw an `Error` with a descriptive message — never return null for an error condition.
4. When `cfg.dryRun` is true: log the action and return `{ dryRun: true }` — do not make any HTTP call.
5. Never read from `process.env` directly — receive the `cfg` object as the first parameter.

---

## Rate Limiting and Retry

There is currently no built-in retry or rate-limit handling in any adapter. This is a known gap.

**Recommended addition**: wrap `adoFetch()`, JIRA, and GitHub API calls with exponential backoff on 429 (rate limited) and 503 (service unavailable) responses. Until implemented, `runIntegration()` will report the failure and continue processing remaining items.
