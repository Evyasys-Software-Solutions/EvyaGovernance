# Localisation and Constants

> Generated by /evyasys:TrainDocs on 2026-06-17.

## Overview

This project is an English-only developer tool. There are no locale files or i18n libraries. User-facing text lives in PROMPT.md workflow files (which are the "templates" for AI responses) and hooks.js console output.

All configurable business values (ID prefixes, Fibonacci scales, Fibonacci velocities, PM tool names) are stored in config files — never hardcoded in hooks.js or scripts.

---

## Team Glossary (`.ai/memory/evyaflow.json`)

The `team_glossary` block in `.ai/memory/evyaflow.json` defines domain terms that the AI agent uses when drafting stories. This is the closest equivalent to a locale file for business terminology.

Current entries:

| Term | Definition |
|---|---|
| `requester` | The person who initiates a business request |
| `approver` | The person who must confirm before the request proceeds |
| `backlog` | The prioritised list of stories ready for development |
| `epic` | A group of related stories delivering one business capability |
| `DoR` | Definition of Ready — gates a story into a sprint |
| `DoD` | Definition of Done — gates a story out of development |
| `AC` | Acceptance Criterion — a testable condition the story must satisfy |

**Rule**: New business terms introduced in project context must be added to `{project}/.evyasys/memory/glossary.json` (project-level), not to `evyaflow.json` (plugin-level). Plugin-level glossary terms are shared across all projects.

## Configurable ID Constants

All story and epic ID values are configurable — never hardcoded.

| Constant | Location | Default | Override |
|---|---|---|---|
| Story ID prefix | `project.yaml → story.id_prefix` | `EVYA` | Per-project |
| Story number start | `evyaflow.json → story_id_counter` | `1001` | Session memory |
| Epic ID prefix | Always `EP-` | — | Not configurable |
| Story point scale | `project.yaml → story.point_scale` | `3,5,8,13,21` | Per-project |
| Team velocity | `project.yaml → story.velocity` | `20` | Per-project |

## Delivery Rule Constants (`.ai/memory/evyaflow.json`)

The `delivery_rules` block defines boolean constants that control AI agent behaviour:

| Constant | Value | Effect |
|---|---|---|
| `business_first` | `true` | AI must draft in business language, no tech implementation in stories |
| `no_tech_in_story` | `true` | AI must reject any technical content in `_UserStory.md` |
| `human_confirmation_required` | `true` | No board action without explicit user approval |
| `dry_run_by_default` | `false` | Default mode is live (real PM calls) |
| `self_review_before_show` | `true` | AI runs CHECKLIST.md + VALIDATION.md before showing output |
| `ask_only_critical_questions` | `true` | AI only asks questions that block a correct story draft |

## Workflow State Constants (`.ai/memory/evyaflow.json`)

| Command | ADO State | Teams Event |
|---|---|---|
| `create-story` | `New` | `story-created` |
| `create-subtask` | `New` | `null` |
| `start-dev` | `In Progress` | `dev-kickoff` |
| `finish-dev` | `Ready for QA` | `dev-finished` |
| `start-qa` | `In QA` | `qa-started` |
| `finish-qa` | `Done` | `qa-finished` |

These state names are the Evyasys canonical values. Each PM adapter maps them to its own state names (e.g., JIRA maps `Ready for QA` to a JIRA transition ID).

## Notification Event Constants (`scripts/lib/notify-adapter.js`)

Valid event names that can be passed to `notify.send(cfg, { event, ... })`:

`story-created` | `epics-created` | `stories-batch-created` | `subtasks-created` | `subtasks-batch-created` | `dev-kickoff` | `review-passed` | `review-no-go` | `dev-finished` | `qa-started` | `qa-finished` | `bug-found` | `release-generated`

**Rule**: Never pass an undeclared event string to `notify.send()`. Add new events to the JSDoc comment in `notify-adapter.js` before using them.

## ADO Work Item Type Constants

Configurable via `project.yaml → work_item_types`. Defaults map to the Agile process template:

| Work item | Default value | Override key |
|---|---|---|
| Epic | `Epic` | `ADO_TYPE_EPIC` env var or `work_item_types.epic` |
| Story | `User Story` | `ADO_TYPE_STORY` env var or `work_item_types.story` |
| Task | `Task` | `ADO_TYPE_TASK` env var or `work_item_types.task` |

For Scrum process template: Epic / Product Backlog Item / Task.
For CMMI process template: Epic / Requirement / Task.
