# Architecture

> Generated by /evyasys:TrainDocs on 2026-06-17.

## Pattern

**Plugin-Orchestration Architecture** — a Claude Code plugin that implements an AI-assisted SDLC delivery pipeline. The system is structured as a sequence of layers: an AI agent follows a PROMPT.md script, produces structured output, and a post-agent hook.js processes that output to execute irreversible side-effects (file saves, PM tool sync, notifications).

This is not a web application. There is no HTTP server, no database, and no frontend UI. It runs entirely on the developer's machine via Claude Code.

## Layer Map

```
Layer 0 — Skill definitions
  skills/evyasys-{command}/SKILL.md      ← Claude Code reads this to load the command
  skills/evyasys-{command}/hooks.js      ← Runs after the AI agent completes

Layer 1 — AI prompt scripts
  .ai/workflows/{command}/PROMPT.md      ← Step-by-step instructions for the AI agent
  .ai/workflows/{command}/AGENT.md       ← Persona / role definition for the AI agent
  .ai/workflows/{command}/CHECKLIST.md   ← Quality checklist the agent self-reviews against

Layer 2 — AI rules (cross-cutting)
  .ai/rules/*.md                         ← Non-negotiable rules loaded by every command
  .evyasys/rules/*.md                    ← Project overrides (wins over plugin defaults)

Layer 3 — Post-agent hooks
  skills/*/hooks.js                      ← Node.js: parses AI output, saves files, syncs PM, notifies

Layer 4 — Script library
  scripts/lib/config.js                  ← Layered config loader (env > credentials > project.yaml > defaults)
  scripts/lib/dryrun.js                  ← Wrapper for all external calls (live vs. dry-run)
  scripts/lib/pm-adapter.js              ← Routes PM operations to the configured tool
  scripts/lib/notify-adapter.js         ← Routes notifications to the configured channel
  scripts/lib/ado-map.js                 ← Evyasys ID ↔ PM tool ID mapping (persisted in .evyasys/.ado-map.json)
  scripts/lib/encrypt.js                 ← AES-256-CBC credential encryption (machine-bound key)

Layer 5 — Integration adapters
  scripts/integrations/azure_devops.js   ← Azure DevOps REST API v7.1
  scripts/integrations/jira.js           ← JIRA REST API
  scripts/integrations/github_board.js   ← GitHub Projects GraphQL API
  scripts/integrations/teams_webhook.js  ← Microsoft Teams incoming webhook
  scripts/integrations/slack_webhook.js  ← Slack incoming webhook
  scripts/integrations/whatsapp.js       ← Twilio WhatsApp API
  scripts/integrations/email.js          ← SMTP via nodemailer

Layer 6 — Config and memory
  {project}/.evyasys/project.yaml        ← Per-project config (committed to git — non-sensitive only)
  ~/.evyasys/credentials                 ← Per-user encrypted secrets (never committed)
  .ai/memory/evyaflow.json               ← Plugin runtime memory (workflow states, glossary, delivery rules)
  {project}/.evyasys/memory/*.json       ← Project-level memory (release history, business terms)

Layer 7 — Project template
  project-template/.evyasys/             ← Scaffolding copied into end-user project repos on first setup
```

## Command Lifecycle

Every command follows this exact sequence:

```
1. User types /evyasys:{Command} [args]
2. Claude Code loads  skills/evyasys-{command}/SKILL.md
3. AI agent reads     .ai/workflows/{command}/PROMPT.md + AGENT.md
4. AI agent reads     .ai/rules/*.md  (+ .evyasys/rules/*.md if present)
5. AI agent runs through PROMPT.md steps — asking questions, reading files, drafting output
6. AI agent produces  delimited output blocks (=== EVYA_STORY: ID === or <!-- EVYABATCH {...} -->)
7. hooks.js fires     skills/evyasys-{command}/hooks.js (post-agent)
8. hooks.js parses    delimited blocks from agent output
9. hooks.js saves     artefact files to .evyasys/board/ (local-first — always succeeds)
10. hooks.js syncs    to PM tool via pm-adapter.js (may fail without blocking local save)
11. hooks.js sends    notifications via notify-adapter.js (fire-and-forget)
12. hooks.js reports  results to user
```

## Output Block Protocol

The AI agent and hooks.js communicate through **delimited output blocks**. The AI embeds these in its response; hooks.js parses them. This is the contract between the AI layer and the execution layer.

| Block type | Delimiter pattern | Produced by | Consumed by |
|---|---|---|---|
| Epic content | `=== EVYA_EPIC: {id} === ... === END_EVYA_EPIC: {id} ===` | CreateStory agent | `hooks.js:parseDelimitedBlocks(text, 'EPIC')` |
| Story content | `=== EVYA_STORY: {id} === ... === END_EVYA_STORY: {id} ===` | CreateStory agent | `hooks.js:parseDelimitedBlocks(text, 'STORY')` |
| Batch manifest | `<!-- EVYABATCH { json } -->` | CreateStory agent | `hooks.js:parseBatchBlock(text)` |
| Setup config | `<!-- EVYACONFIG { json } -->` | Setup agent | Setup hooks.js |
| Release data | `<!-- EVYARELEASE { json } -->` | GenerateReleaseNote agent | GenerateReleaseNote hooks.js |
| Doc content | `<!-- EVYADOC: FILENAME.md -->` | TrainDocs agent | TrainDocs hooks.js |

## Config Resolution Order

```
Highest priority ──▶  Lowest priority
process.env  ──▶  ~/.evyasys/credentials  ──▶  .evyasys/project.yaml  ──▶  .ai/manifest.yaml defaults
```

Implemented in `scripts/lib/config.js:loadConfig()`.

## Anti-Patterns

- **Never write integration code directly in hooks.js.** All PM and notification calls go through `pm-adapter.js` and `notify-adapter.js` so the hook is decoupled from the specific tool.
- **Never call `node-fetch` directly from hooks.js.** All HTTP calls go through `runIntegration()` in `scripts/lib/dryrun.js` so dry-run mode intercepts them.
- **Never save secrets to project.yaml.** project.yaml is committed to git. Secrets live in `~/.evyasys/credentials`.
- **Never block on PM sync.** Local file save must succeed regardless of PM tool connectivity. PM sync is fire-and-continue.
- **Never parse AI output with fragile regex in hooks.js.** Parsing logic must use the canonical `parseDelimitedBlocks()` and `parseBatchBlock()` functions so all hooks share the same parser.
- **Never add a new command without a corresponding SKILL.md + hooks.js.** Undeclared commands are not loaded by Claude Code.
