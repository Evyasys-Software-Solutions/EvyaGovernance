## Required Test Coverage (Priority Order)

### 1. Unit tests for parser functions (Highest priority)

The `parseDelimitedBlocks()` and `parseBatchBlock()` functions are the most critical code in the plugin — a parsing bug silently drops story content or creates wrong artefacts.

**Test cases required**:
- `parseBatchBlock()` with a valid EVYABATCH block → returns correct JSON
- `parseBatchBlock()` with malformed JSON inside the block → returns null
- `parseBatchBlock()` with no EVYABATCH block → returns null
- `parseDelimitedBlocks(text, 'STORY')` with one story → returns `{ 'EVYA-1042': content }`
- `parseDelimitedBlocks(text, 'STORY')` with two stories → returns map with two entries
- `parseDelimitedBlocks(text, 'STORY')` with mismatched end tag → skips the block, does not throw
- `parseDelimitedBlocks(text, 'EPIC')` basic extraction
- Parser with realistic multi-story agent output (regression test for any future changes)

### 2. Unit tests for `scripts/lib/encrypt.js`

- `encrypt(plaintext)` returns a string in `{ivHex}:{ciphertextHex}` format
- `decrypt(encrypt(value))` round-trip returns the original value
- `decrypt(plaintext)` (no colon, not encrypted) returns the value as-is (legacy compatibility)
- `decrypt('')` returns empty string without throwing
- `decrypt(malformed)` returns value as-is without throwing

### 3. Unit tests for `scripts/lib/config.js`

- `loadConfig()` resolves `pm_tool` from `process.env` when set
- `loadConfig()` falls back to `project.yaml` when env var absent
- `loadConfig()` falls back to `'local'` when neither env nor project.yaml is set
- `loadConfig()` detects `azure_devops` legacy block and defaults to `pmTool: 'devops'`
- `loadConfig()` detects Teams webhook and defaults to `notificationTool: 'teams'`

### 4. Unit tests for `scripts/lib/ado-map.js`

- `save()` + `lookup()` round-trip for epic (plain number value)
- `save()` + `lookup()` round-trip for story (`{ adoId, dir }` object)
- `save()` merges with existing entries without overwriting unrelated keys
- `lookup()` returns null for unknown ID
- `lookupDir()` returns dir string for a story, null for an epic

### 5. Integration tests for `scripts/lib/dryrun.js`

- `runIntegration()` with `cfg.dryRun = true` → logs, returns `{ dryRun: true }`, does not call `live()`
- `runIntegration()` with `cfg.dryRun = false` and successful `live()` → returns `{ result }`
- `runIntegration()` with `cfg.dryRun = false` and `live()` throwing → returns `{ error }`, does not re-throw

### 6. Integration tests for hooks.js (CreateStory)

Test with a real filesystem (temp directory) and mocked PM adapter:
- Complete batch with 1 new epic + 1 story → files created at correct paths
- Story with PM sync failure → local file still created, no throw
- Missing EVYABATCH block → sends "no output block found" message, no files created
- Epic with `"status": "existing"` → no epic file created, story linked correctly

## Mocking Strategy

- **File system**: Use `memfs` or Jest's `fs` mock to avoid writing real files in tests.
- **External HTTP**: Mock `node-fetch` at the module level — never make real API calls in tests.
- **`cfg.dryRun`**: Set to `true` in all integration tests unless specifically testing live-mode behaviour.
- **`process.env`**: Set and restore in `beforeEach` / `afterEach` using `jest.replaceProperty()`.
