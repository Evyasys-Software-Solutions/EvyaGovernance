# Onboarding

> Generated by /evyasys:TrainDocs on 2026-06-17. From zero to your first story in 15 minutes.

---

| Requirement | Version | Check |

## Step 1 — Get the plugin

```bash
git clone <evyagovernance-repo-url>
cd EvyaGovernance
npm install
```

Verify the config loader works:
```bash
npm run setup
# Expected: "Config loader OK"
```

---

## Step 2 — Set up in your project

Navigate to the project repo where you will use the plugin:

```bash
cd /path/to/your-project
```

Copy the project template:
```bash
cp -r /path/to/EvyaGovernance/project-template/.evyasys ./.evyasys
```

Open Claude Code in your project:
```bash
claude
```

Run the setup wizard:
```
/evyasys:Setup
```

The wizard will:
1. Detect `.evyasys/` and ask you to confirm the project name.
2. Ask which PM tool to use — choose from: **Azure DevOps**, **JIRA**, **GitHub Projects**, or **Local (no PM tool)**.
3. Collect the PM tool credentials and validate them live with an API call.
4. Ask which notification channel to use — choose from: **Teams**, **Slack**, **WhatsApp**, **Email**, or **None**.
5. Collect and validate notification credentials.
6. Write `project.yaml` and save credentials encrypted.

## Step 4 — Verify with a dry run

```bash
EVYASYS_DRY_RUN=1
/evyasys:CreateStory
```

You should see the input gate prompt. Select option A ("Describe it here"). Type any brief description. The agent will draft a story but — with dry-run active — will not push anything to your PM tool.

---

## Step 5 — Create your first real story

```
/evyasys:CreateStory
```

Select how you want to provide requirements:
- **A — Describe it here**: Answer the agent's guided questions one at a time.
- **B — Reference document**: Provide a path to a requirements doc, transcript, or brief. The agent performs a full BA + Architect analysis before asking only the blocking questions.

After questions are answered, the agent will:
1. Resolve or propose epics (Gate 1 — confirm new epics).
2. Plan the story batch (Gate 2 — approve IDs, SPs, and titles).
3. Draft all stories with self-review.
4. Show you a confirmation prompt before saving or pushing anything.

## Environment Variable Reference

| Variable | Purpose | Set where |
|---|---|---|
| `EVYASYS_DRY_RUN` | `1` to preview without any API calls | Shell export or `.env` |
| `EVYASYS_REPO_ROOT` | Override project root path (for CI) | Shell export |
| `AZURE_PAT` | Azure DevOps PAT (override credentials file) | `~/.evyasys/credentials` (via Setup) |
| `AZURE_ORG` | Azure DevOps org | `project.yaml → azure_devops.org` |
| `AZURE_PROJECT` | Azure DevOps project | `project.yaml → azure_devops.project` |
| `TEAMS_WEBHOOK` | Teams channel webhook | `project.yaml → teams.webhook` |

Full catalog: see CONFIGURATION_MANAGEMENT.md.

## Common Problems

| Problem | Cause | Fix |
|---|---|---|
| `No PAT available. Run scripts/login.sh` | Credentials not set up | Run `/evyasys:Setup` or `scripts/login.sh` |
| `AZURE_ORG / AZURE_PROJECT not set` | project.yaml not configured | Check `.evyasys/project.yaml` has `azure_devops.org` and `azure_devops.project` |
| `No EVYABATCH block found` | AI agent didn't complete story planning | Ask the agent to complete the story plan and output the EVYABATCH block |
| PM sync returns 401 | PAT expired | Revoke old PAT, generate new one, re-run `/evyasys:Setup` |
| PM sync returns 403 | PAT missing Work Items: Write scope | Generate a new PAT with `Work Items: Read & Write` scope |
| Story content missing from PM tool | Story ID was in manifest but content block was absent | Re-run CreateStory — local `.md` file is safe; only PM sync was incomplete |
| `python3: command not found` | Python not installed | Install Python 3.x — repo scanner will fail gracefully and agent continues without it |
| Teams notification not arriving | Webhook URL wrong or Teams connector expired | Re-run `/evyasys:Setup` → re-enter Teams webhook URL |

## Commands Reference

| Command | What it does | Typical time |
|---|---|---|
| `/evyasys:Setup` | Configure PM tool + notification for this project | 3 min |
| `/evyasys:CreateStory` | Draft epics and stories, sync to PM tool | 5–10 min |
| `/evyasys:CreateSubtask` | Break a story into subtasks | 3–5 min |
| `/evyasys:StartDev <EVYA-ID>` | Tech brainstorm + start dev gate | 5 min |
| `/evyasys:ReviewDev <EVYA-ID>` | Code review checklist | 3 min |
| `/evyasys:FinishDev <EVYA-ID>` | AC coverage audit + Dev Summary | 5 min |
| `/evyasys:StartQa <EVYA-ID>` | Test plan generation | 5 min |
| `/evyasys:FinishQa <EVYA-ID>` | QA sign-off + release notes | 5 min |
| `/evyasys:GenerateReleaseNote` | Branded PDF release document | 3 min |
| `/evyasys:TrainDocs` | Generate quality-gate docs for the project | 10–15 min |

## Project Workspace Layout

After setup, your project will have:

```
{your-project}/
└── .evyasys/
    ├── project.yaml          ← Edit this for PM/notification config
    ├── board/                ← All story artefacts (auto-generated)
    ├── docs/                 ← Quality-gate docs (from /evyasys:TrainDocs)
    ├── memory/               ← Business knowledge (edit freely)
    ├── rules/                ← Override plugin defaults (optional)
    ├── workflows/            ← Override prompts (optional)
    └── inputs/               ← Drop requirement docs here
```

Full reference: `project-template/.evyasys/README.md`.
