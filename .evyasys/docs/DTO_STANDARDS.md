# DTO Standards — Output Block Protocol

> Generated by /evyasys:TrainDocs on 2026-06-17.

There are no HTTP request/response DTOs in this project. The equivalent is the **Output Block Protocol** — the structured text format the AI agent embeds in its response, which hooks.js parses and processes.

---

## Output Block Types

### 1. EVYA_STORY — Story content block

Used by: CreateStory command.
Parsed by: `parseDelimitedBlocks(text, 'STORY')` in `skills/evyasys-create-story/hooks.js`.

```
=== EVYA_STORY: EVYA-1042 ===
# EVYA-1042 — Story Title

Status: Backlog
Epic: EP-001
Story Points: 5

## Business Context
...

## Acceptance Criteria
...
=== END_EVYA_STORY: EVYA-1042 ===
```

**Rules**:
- The ID in the opening and closing delimiter must match exactly (case-sensitive).
- The content is a complete `STORY_TEMPLATE.md` fill — no partial content.
- Story metadata (`Status:`, `Epic:`, `Story Points:`) must appear as plain key-value lines before the first `##` section so `azure_devops.js` can strip them before posting.

### 2. EVYA_EPIC — Epic content block

Used by: CreateStory command.
Parsed by: `parseDelimitedBlocks(text, 'EPIC')` in `skills/evyasys-create-story/hooks.js`.

```
=== EVYA_EPIC: EP-003 ===
# EP-003 — Epic Title

Status: Draft
Priority: Medium
Owner:

## Epic Goal
...

## Linked Stories
EVYA-1001, EVYA-1002
=== END_EVYA_EPIC: EP-003 ===
```

### 3. EVYABATCH — Batch manifest

Used by: CreateStory command.
Parsed by: `parseBatchBlock(text)` in `skills/evyasys-create-story/hooks.js`.

Must appear as the last block in the agent output. Contains the full list of epics and stories for the hook to process.

```
<!-- EVYABATCH
{
  "epics": [
    { "epicId": "EP-003", "title": "Customer Authentication", "status": "new" },
    { "epicId": "EP-001", "title": "Core Platform", "status": "existing" }
  ],
  "stories": [
    { "storyId": "EVYA-1001", "epicId": "EP-003", "title": "User Login", "points": 5 },
    { "storyId": "EVYA-1002", "epicId": "EP-003", "title": "Registration Flow", "points": 8 }
  ]
}
-->
```

**Field contracts**:

| Field | Type | Required | Values |
|---|---|---|---|
| `epics[].epicId` | string | Yes | `EP-{3 digits}` |
| `epics[].title` | string | Yes | Human-readable epic name |
| `epics[].status` | string | Yes | `"new"` or `"existing"` |
| `stories[].storyId` | string | Yes | `{PREFIX}-{number}` |
| `stories[].epicId` | string | Yes | Must match an `epicId` in the `epics` array |
| `stories[].title` | string | Yes | Human-readable story title |
| `stories[].points` | number | Yes | From project.yaml `point_scale` |

**Rules**:
- Every story's `epicId` must appear in the `epics` array. If not, the hook logs a warning and saves the story locally without PM epic linkage.
- `"status": "existing"` means the hook resolves the PM tool ID from `.ado-map.json` rather than creating a new epic.
- Only new epics need `EVYA_EPIC` content blocks. Existing epics need only their `epicId` in the manifest.

### 4. EVYACONFIG — Setup config block

Used by: Setup command.
Parsed by: Setup hooks.js.

```
<!-- EVYACONFIG
{
  "pmTool": "devops",
  "azure": { "org": "EvyaCorp", "project": "CustomerPortal" },
  "notificationTool": "teams",
  "teams": { "webhook": "https://..." }
}
-->
```

**Rule**: Secrets (PAT, API tokens) must never appear in the EVYACONFIG block. The Setup agent collects them separately and the hook writes them directly to `~/.evyasys/credentials` via `writeUserCreds()`.

### 6. EVYADOC — TrainDocs document block

Used by: TrainDocs command.
Parsed by: TrainDocs hooks.js.

```
<!-- EVYADOC: ARCHITECTURE.md -->
# Architecture
...

<!-- EVYADOC: RULES.md -->
# Rules
...
```

**Rule**: The document filename in the delimiter must match exactly the target filename in `.evyasys/docs/`. Subdirectory paths are supported: `<!-- EVYADOC: fe/STYLING_MICRO_STANDARDS.md -->`.

## ADO Content Stripping

When posting story content to Azure DevOps, the integration strips metadata before creating the work item. This is not a DTO transformation — it is a pre-post sanitisation. Defined in `scripts/integrations/azure_devops.js`.

Stripped content:
- Key-value metadata header lines before the first `##` heading (Status, Epic, Priority, Module, Owner, etc.)
- The `## Confirmation` section and all content after it

The local `.md` file is never modified.
