# Deployment

> Generated by /evyasys:TrainDocs on 2026-06-17.

## Deployment Model

This is a Claude Code plugin — there is no web server to deploy. "Deployment" means two things:

1. **Plugin distribution**: Making a new plugin version available to developers.
2. **Project bootstrap**: Setting up the plugin in a new project repository.

---

## Plugin Distribution

### Current distribution method

The plugin is distributed by sharing the plugin repository directly (git clone or copy). There is no npm publish step or Claude Code plugin registry as of v0.2.0.

### Releasing a new plugin version

1. Update `package.json → version` following semver.
2. Update `CHANGELOG.md` (or `DECISIONS.md`) with what changed.
3. Commit with message: `chore: release v{version}`.
4. Tag the commit: `git tag v{version} && git push origin v{version}`.
5. Notify the team to pull the latest tag.

### Updating an existing plugin installation

```bash
# Pull latest changes to the plugin repo
git pull origin main

# Verify Node.js dependencies are up to date
npm install

# Run config loader sanity check
npm run setup
```

## Project Bootstrap (setting up a new project)

When a developer wants to use Evyasys in a new project repository for the first time:

**Step 1 — Copy the project template**:
```bash
# From the plugin root
cp -r project-template/.evyasys /path/to/your-project/.evyasys
```

**Step 2 — Configure the project**:
Run `/evyasys:Setup` in Claude Code from the project directory. The Setup wizard will:
- Detect the new `.evyasys/` directory
- Ask which PM tool to use (Azure DevOps / JIRA / GitHub / Local)
- Collect and validate credentials
- Ask which notification channel to use (Teams / Slack / WhatsApp / Email / None)
- Write `project.yaml` with non-sensitive config
- Write encrypted credentials to `~/.evyasys/credentials`

**Step 3 — Commit project config**:
```bash
cd /path/to/your-project
git add .evyasys/project.yaml
git commit -m "chore: add evyasys project config"
```

**Step 4 — Add to `.gitignore`** (the template already includes this, but verify):
```
.evyasys/.env
```

**Step 5 — Verify**:
```bash
# Test with dry-run mode
EVYASYS_DRY_RUN=1 /evyasys:CreateStory
# Should show the input gate without making any API calls
```

## Per-Developer Setup (first time on a machine)

```bash
# macOS/Linux
bash scripts/login.sh

# Windows
.\scripts\setup.ps1
```

These scripts prompt for the Azure DevOps PAT and save it encrypted to `~/.evyasys/credentials`. Run once per machine. Re-run when credentials expire.

---

## Credential Rotation Procedure

1. Revoke the old PAT/token in the PM tool's admin console.
2. Generate a new credential with the minimum required scope (see SECURITY.md).
3. Run `/evyasys:Setup` → re-enter the new credential → Setup validates it live.
4. Or run `scripts/login.sh` / `scripts/setup.ps1` directly.

## Environment-Specific Notes

| Environment | `pm_tool` setting | `EVYASYS_DRY_RUN` | Credentials |
|---|---|---|---|
| Developer machine | `devops` / `jira` / `github` | `0` (live) | `~/.evyasys/credentials` |
| CI/CD pipeline | `local` (no PM writes from CI) | `1` recommended | CI secret store → `AZURE_PAT` env var |
| Demo / presentation | `local` or `devops` with a test project | `1` | Demo credentials in `~/.evyasys/credentials` |

## Rollback Procedure

If a plugin update breaks something:

```bash
# Return to the previous tag
git checkout v{previous-version}
npm install
```

All artefacts in `.evyasys/board/` are untouched — they are in the project repo, not the plugin repo.

## Pre-Deploy Checklist

Before releasing a new version:
- [ ] `package.json version` incremented
- [ ] All new commands have SKILL.md + hooks.js + PROMPT.md + entries in `commands.yaml`
- [ ] `project-template/.evyasys/` updated if new project-level files are required
- [ ] `.env.example` updated with any new environment variables
- [ ] `ONBOARDING.md` updated if setup steps changed
- [ ] `npm run setup` passes (config loader sanity check)
- [ ] Manual end-to-end test with `EVYASYS_DRY_RUN=1` on a test project
