# Glossary

> Generated by /evyasys:TrainDocs on 2026-06-17.

## Plugin and System Terms

| Term | Definition |
|---|---|
| **Evyasys** | The Claude Code plugin that implements the AI-assisted SDLC delivery pipeline. The plugin name is also the npm package name (`evyasys`). |
| **Evyasys ID** | The unique identifier for a story or epic within the plugin. Format: `{PREFIX}-{number}` for stories (e.g., `EVYA-1042`) and `EP-{3 digits}` for epics (e.g., `EP-001`). Distinct from the PM tool's own numeric ID. |
| **SKILL.md** | The Claude Code descriptor file that defines a command's trigger, description, and capabilities. Claude Code reads this file to load the command. |
| **hooks.js** | The Node.js post-agent hook that runs after the AI agent completes. It parses the AI output, saves artefacts, syncs to the PM tool, and sends notifications. |
| **PROMPT.md** | The step-by-step instruction file that the AI agent follows when executing a command. Defines the gates, questions, output format, and quality standards. |
| **Gate** | A hard confirmation checkpoint in a command workflow. The AI presents a summary and waits for explicit user approval before proceeding with irreversible actions. Marked with `⛔` in PROMPT.md. |
| **Output Block Protocol** | The structured delimiter format (`=== EVYA_STORY: ID ===`, `<!-- EVYABATCH {...} -->`) that the AI agent embeds in its response for hooks.js to parse. |
| **EVYABATCH** | The JSON manifest block embedded in the AI agent's output by the CreateStory command. Contains the full list of epics and stories with metadata for the hook to process. |
| **EVYACONFIG** | The JSON config block output by the Setup command. Contains non-sensitive project config for `project.yaml`. |
| **EVYARELEASE** | The JSON block output by GenerateReleaseNote. Contains version, date, story IDs, and markdown content for the PDF generator. |
| **EVYADOC** | The delimiter used by TrainDocs to mark the start of each generated document file (`<!-- EVYADOC: FILENAME.md -->`). |
| **runIntegration()** | The wrapper function in `scripts/lib/dryrun.js` that intercepts all external API calls. Returns `{ dryRun: true }` in dry-run mode, `{ result }` on success, or `{ error }` on failure — never throws. |
| **pm-adapter** | `scripts/lib/pm-adapter.js` — routes PM operations (createEpic, createStory, setState, createBug) to the configured PM tool adapter. |
| **notify-adapter** | `scripts/lib/notify-adapter.js` — routes team notifications to the configured channel adapter. |
| **ado-map** | `scripts/lib/ado-map.js` — persists the mapping between Evyasys IDs and PM tool numeric IDs in `.evyasys/.ado-map.json`. |
| **Dry-run mode** | When `EVYASYS_DRY_RUN=1`, all external API calls are skipped. The plugin logs what it would do and saves local files normally. Used for testing and CI. |
| **Local-first** | The principle that artefact files are always written to local disk before PM sync is attempted. A PM sync failure never prevents the local file from being created. |
| **Back-write** | The process of writing the PM tool's numeric ID (returned after creating a work item) back into the local markdown artefact file for traceability. |
| **Machine-bound key** | The AES-256-CBC encryption key derived from `sha256("evyasys:{hostname}:{username}")` used to encrypt `~/.evyasys/credentials`. Credentials encrypted on one machine cannot be decrypted on another. |

## Business Delivery Terms

| Term | Definition |
|---|---|
| **Requester** | The person who initiates a business request. The actor whose goal drives the story. |
| **Approver** | The person who must confirm before a business request proceeds to the next stage. |
| **Epic** | A group of related user stories delivering one cohesive business capability. An epic spans multiple sprints. |
| **User Story** | A single piece of business value deliverable in one sprint. Written in business language — no technical implementation details. |
| **AC** | Acceptance Criterion — a testable, independently verifiable condition the story must satisfy. Each AC must map to at least one test. |
| **DoR** | Definition of Ready — the checklist a story must pass before it enters a sprint. |
| **DoD** | Definition of Done — the checklist development must pass before a story can move to Ready for QA. |
| **Story Point (SP)** | A relative estimate of effort using the Fibonacci scale (`3, 5, 8, 13, 21` by default). Not hours. |
| **Tech Brainstorm** | The structured analysis of implementation approaches (minimum 3) produced by `/evyasys:StartDev`. Recommends one approach with a clear deciding reason. Saved as `_TechBrainstorm.md`. |
| **Dev Summary** | The QA handoff document produced by `/evyasys:FinishDev`. Contains files touched, AC coverage table, risks, and QA hints. Saved as `_DevSummary.md`. |
| **Test Plan** | The structured QA plan produced by `/evyasys:StartQa`. Contains test cases, environment, test data requirements, and regression scope. |
| **Reference Doc Archive** | When CreateStory Path B is used, the original reference document is copied to `.evyasys/board/referencedoc/{date}/` with the BA+Architect analysis and Q&A appended. Provides the traceability chain from "what was asked" to "what was built". |
| **PM Tool** | Project Management Tool — the external board system where stories and epics are tracked. Supported: Azure DevOps, JIRA, GitHub Projects, or Local (no tool). |
| **Impacted Areas** | The architectural domains that a story touches: Security, DB, Frontend, API, Performance. Flagged as checkboxes in the story template. |
