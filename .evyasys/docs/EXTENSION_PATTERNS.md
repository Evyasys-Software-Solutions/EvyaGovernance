# Extension Patterns

> Generated by /evyasys:TrainDocs on 2026-06-17.

## How the system grows

New commands, integrations, and adapters are added by **extension** — not by modifying existing core modules. Adding a new PM tool means adding one new file under `scripts/integrations/` and one routing line in `scripts/lib/pm-adapter.js`. Nothing else changes.

---

## Adding a New Command

**Required files** — all must be created:

| File | Purpose |
|---|---|
| `skills/evyasys-{command}/SKILL.md` | Claude Code skill descriptor (frontmatter + description + what it does) |
| `skills/evyasys-{command}/hooks.js` | Post-agent hook — parses AI output, saves files, calls adapters |
| `.ai/workflows/{command}/PROMPT.md` | Step-by-step AI agent instructions |
| `.ai/workflows/{command}/AGENT.md` | AI persona and role definition |
| `.ai/workflows/{command}/CHECKLIST.md` | Quality checklist for self-review |

**Registration** — add to `.ai/commands.yaml`:
```yaml
my-new-command:
  trigger: /evyasys:MyNewCommand
  skill: evyasys-my-new-command
  agent: workflows/my-new-command/AGENT.md
  prompt: workflows/my-new-command/PROMPT.md
  checklist: workflows/my-new-command/CHECKLIST.md
```

**hooks.js skeleton**:
```js
const { loadConfig }      = require('../../scripts/lib/config');
const { runIntegration }  = require('../../scripts/lib/dryrun');
const pm                  = require('../../scripts/lib/pm-adapter');
const notify              = require('../../scripts/lib/notify-adapter');

module.exports = async function (ctx) {
  const cfg    = await loadConfig({ ctx });
  const output = ctx.agentResult || '';

  // 1. Parse delimited blocks from AI output
  // 2. Single confirmation gate
  if (!(await ctx.confirm(`Confirm action?`))) { ctx.send('Cancelled.'); return; }
  // 3. Save locally first
  // 4. PM sync via runIntegration()
  // 5. Notify via runIntegration()
};
```

## Adding a New PM Tool Integration

**Required files**:
- `scripts/integrations/{tool-name}.js` — must export: `findEpic`, `createEpic`, `createStory`, `createSubtasks`, `setState`, `createBug`

**Registration** — add one routing line per operation in `scripts/lib/pm-adapter.js`:
```js
if (cfg.pmTool === 'mytool') return require('../integrations/my-tool').createStory(params);
```

**Add config support** in `scripts/lib/config.js:loadConfig()`:
```js
const myTool = {
  apiUrl:  process.env.MYTOOL_API_URL  || (project.mytool && project.mytool.api_url)  || '',
  apiKey:  process.env.MYTOOL_API_KEY  || userCreds.MYTOOL_API_KEY                    || '',
};
```

**Add credential helper** in `scripts/lib/config.js`:
```js
async function ensureMyToolCreds(cfg) {
  if (cfg.myTool.apiKey) return;
  const key = await prompt('MyTool API key: ');
  writeUserCreds({ MYTOOL_API_KEY: key });
  cfg.myTool.apiKey = key;
}
```

**Valid pm_tool values** (update `LABELS` in `pm-adapter.js`): `local | devops | jira | github | {new-tool}`

## Adding a New Notification Channel

**Required files**:
- `scripts/integrations/{channel-name}.js` — must export: `send(cfg, { event, storyId, ...extras })`

**Registration** in `scripts/lib/notify-adapter.js`:
```js
if (tool === 'mychannel') {
  const mc = require('../integrations/my-channel');
  return mc.send({ event, storyId, ...extras });
}
```

**Credential helper**: add `ensureMyChannelCreds(cfg)` to `scripts/lib/config.js` following the same pattern as `ensureTeamsWebhook()`.

## Script Library Contracts

These modules are the stable API that all hooks and integrations depend on. Their exported function signatures must not change without updating all callers.

### `scripts/lib/config.js`
```
loadConfig({ ctx? })                   → Promise<cfg>
writeUserCreds(updates)                → string (file path)
readUserCreds()                        → object
prompt(question)                       → Promise<string>
ensurePat(cfg)                         → Promise<string>
ensureJiraCreds(cfg)                   → Promise<void>
ensureGitHubToken(cfg)                 → Promise<void>
ensureTeamsWebhook(cfg)                → Promise<void>
ensureSlackWebhook(cfg)                → Promise<void>
ensureWhatsAppCreds(cfg)               → Promise<void>
ensureEmailCreds(cfg)                  → Promise<void>
```

### `scripts/lib/dryrun.js`
```
runIntegration({ name, cfg, args, live })  → Promise<{ dryRun?, result?, error? }>
```

### `scripts/lib/pm-adapter.js`
```
toolLabel(cfg)                         → string
ensureCredentials(cfg)                 → Promise<void>
findEpic(cfg, { epicId })              → Promise<id|null>
createEpic(cfg, { epicId, title })     → Promise<{ id }|null>
createStory(cfg, { storyId, file, epicId })  → Promise<{ id }|null>
createSubtasks(cfg, params)            → Promise<array>
setState(cfg, { storyId, state })      → Promise<result|null>
createBug(cfg, params)                 → Promise<result|null>
```

### `scripts/lib/notify-adapter.js`
```
toolLabel(cfg)                                       → string
ensureCredentials(cfg)                               → Promise<void>
send(cfg, { event, storyId, ...extras })             → Promise<result>
```

### `scripts/lib/ado-map.js`
```
save(repoRoot, entries)                → void
lookup(repoRoot, evyasysId)            → number|null
lookupDir(repoRoot, evyasysId)         → string|null
```

### `scripts/lib/encrypt.js`
```
encrypt(plaintext)                     → string  "<ivHex>:<ciphertextHex>"
decrypt(encoded)                       → string
```

## Refactor Debt

| Item | Location | Issue | Priority |
|---|---|---|---|
| Parallel Python/JS ADO implementations | `azure_devops.py` and `azure_devops.js` | Two implementations of the same integration will diverge. Node.js version should be canonical; Python version should call the JS version or be removed. | High |
| Parallel Python/JS Teams implementations | `teams_webhook.py` and `teams_webhook.js` | Same divergence risk as ADO | High |
| Missing `evyaflow.json` runtime update | `evyaflow.json → story_id_counter` | Counter is initialised to 1001 but hooks.js scans the board folder to find the actual next ID rather than reading/updating this counter. The counter field is misleading. | Medium |
| `azure_devops.js` uses snake_case filename | `scripts/integrations/azure_devops.js` | Inconsistent with kebab-case convention for new JS files | Low |
