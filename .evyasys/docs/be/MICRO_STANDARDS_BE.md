# Backend Micro Standards

> Generated by /evyasys:TrainDocs on 2026-06-17.

These are the micro-level contracts for the three main "layers" of this plugin's backend: **hooks.js** (the controller layer), **script library modules** (the service layer), and **integration adapters** (the repository/gateway layer).

---

## Layer 1 — hooks.js (Controller equivalent)

### Contract

A hooks.js is the entry point for a command. It must:
1. Call `loadConfig()` first — nothing else runs before config is loaded.
2. Parse AI output using canonical parser functions — never ad-hoc regex.
3. Show one confirmation gate (`ctx.confirm()`) before any file write or external call.
4. Write local files before PM sync (`fs.writeFileSync` before `runIntegration(pm.createStory)`).
5. Never call integration adapters directly — always via `pm-adapter.js` and `notify-adapter.js`.
6. Report a summary to the user via `ctx.send()` at the end.

### ✅ Correct

```js
module.exports = async function (ctx) {
  const cfg    = await loadConfig({ ctx });          // ✅ first
  const output = ctx.agentResult || '';
  const batch  = parseBatchBlock(output);
  if (!batch) { ctx.send('No EVYABATCH block.'); return; }

  if (!(await ctx.confirm(`Save ${batch.stories.length} stories?`))) {   // ✅ gate before action
    ctx.send('Cancelled.'); return;
  }

  for (const story of batch.stories) {
    fs.writeFileSync(storyPath, content, 'utf8');                        // ✅ local first
    const r = await runIntegration({ live: () => pm.createStory(...) }); // ✅ via adapter
    if (r.error) ctx.send(`⚠️ ${story.storyId} sync failed: ${r.error}`); // ✅ non-fatal
  }
  ctx.send(`Done — ${batch.stories.length} stories saved.`);             // ✅ summary
};
```

### ❌ Wrong

```js
module.exports = async function (ctx) {
  // ❌ config not loaded — all values would be undefined
  // ❌ direct fetch call bypassing runIntegration
  const res = await fetch(`https://dev.azure.com/${process.env.AZURE_ORG}/...`);

  // ❌ PM sync before local save — loss of data if sync fails
  await adoFetch(cfg, ...);
  fs.writeFileSync(storyPath, content);

  // ❌ direct import of integration — bypasses adapter routing
  const ado = require('../../scripts/integrations/azure_devops');
  await ado.createStory(params);
};
```

## Layer 2 — Script library modules (Service equivalent)

### Contract

Script library modules (`scripts/lib/*.js`) are stateless helper functions. They must:
1. Export named functions only (`module.exports = { fn1, fn2 }`) — no class instances.
2. Receive `cfg` as their first parameter — never read `process.env` directly.
3. Never make external HTTP calls — they set up and route; adapters make the calls.
4. Be pure or near-pure — no filesystem side-effects except `config.js:writeUserCreds()` and `ado-map.js:save()` which are explicitly state-management functions.
5. Be independently importable — no circular dependencies.

### ✅ Correct — `pm-adapter.js`

```js
async function createStory(cfg, params) {       // ✅ receives cfg, not process.env
  if (cfg.pmTool === 'local')  return null;     // ✅ null for no-op, not undefined
  if (cfg.pmTool === 'devops') return require('../integrations/azure_devops').createStory(params);
  if (cfg.pmTool === 'jira')   return require('../integrations/jira').createStory(params);
  return null;                                   // ✅ safe default
}
module.exports = { createStory, ... };           // ✅ named exports
```

### ❌ Wrong

```js
// ❌ reads process.env directly — breaks layered resolution
async function createStory(params) {
  const org = process.env.AZURE_ORG;
  ...
}

// ❌ default export — harder to tree-shake and test
module.exports = { createStory };
// should be: module.exports = { toolLabel, ensureCredentials, findEpic, createEpic, createStory, ... }
```

## Layer 3 — Integration adapters (Gateway equivalent)

### Contract

Integration adapters (`scripts/integrations/*.js`) make the actual external API calls. They must:
1. Export the same function names as other adapters for the same operation.
2. Throw a descriptive `Error` on API failure — never return null for an error.
3. Return `{ dryRun: true }` when `cfg.dryRun` is true — never make real HTTP calls in dry-run.
4. Use `node-fetch` (or native `fetch` if available) — never `axios`, `got`, or other HTTP libraries without approval.
5. Not write to local files — local saves are the hook's responsibility.

### ✅ Correct — `azure_devops.js:adoFetch()`

```js
async function adoFetch(cfg, suffix, { method = 'GET', body } = {}) {
  const url = adoUrl(cfg, suffix);
  if (cfg.dryRun) {                               // ✅ dry-run check first
    console.log(`[evyasys:dry-run] ADO ${method} ${url}`);
    return { dryRun: true };
  }
  if (!cfg.azure.org || !cfg.azure.project) {     // ✅ validate before HTTP call
    throw new Error('AZURE_ORG / AZURE_PROJECT not set...');
  }
  const fetchFn = typeof fetch !== 'undefined' ? fetch : require('node-fetch');  // ✅ native-first
  const res = await fetchFn(url, { method, headers: { ... }, body: ... });
  if (!res.ok) throw new Error(`ADO ${method} ${url} failed: ${res.status} ${await res.text()}`); // ✅ descriptive error
  return res.json();
}
```

### ❌ Wrong

```js
async function adoFetch(cfg, suffix) {
  // ❌ no dry-run check
  // ❌ no config validation before calling
  // ❌ returns null on error instead of throwing
  try {
    const res = await fetch(adoUrl(cfg, suffix));
    return res.ok ? res.json() : null;
  } catch {
    return null;                                   // ❌ silent failure
  }
}
```

## Error Flow Ownership

| Layer | What it handles | What it passes up |
|---|---|---|
| Integration adapter | HTTP errors (non-2xx) → throw descriptive Error | — |
| `runIntegration()` | Catches thrown errors → returns `{ error: msg }` | Cleaned result object |
| hooks.js | Checks `result.error` → sends warning to user, continues batch | Batch summary |

No layer is allowed to silently swallow an error. Each layer either handles it (with a user-visible message) or converts it to a structured result that the next layer can inspect.

## Transaction Ownership (File Operations)

Because there is no database, "transactions" in this plugin are filesystem write sequences.

**Rule**: If a hooks.js writes multiple files for one artefact (e.g., epic file + story file + ado-map update), it must write all files before calling PM sync for any of them. A partial write is better than no write — PM IDs can be back-written later; missing artefact files are unrecoverable.

```
✅ Correct order:
1. fs.writeFileSync(epicFile)
2. fs.writeFileSync(storyFile)
3. adoMap.save(cfg.repoRoot, { [storyId]: { adoId: null, dir: storiesDir } })
4. runIntegration({ live: () => pm.createStory(...) })
5. adoMap.save(..., { [storyId]: { adoId: result.id, dir: storiesDir } })  // update with real ID

❌ Wrong order:
1. runIntegration(pm.createStory) — PM might fail, local file never written
2. fs.writeFileSync(storyFile)
```
