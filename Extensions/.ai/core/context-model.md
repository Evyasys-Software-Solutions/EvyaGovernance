# Context Model

Every workflow should gather context from these sources when available:

1. Request input
   - docs
   - wireframes
   - transcripts
   - screenshots
   - user notes

2. Repository context
   - existing code
   - nearby modules
   - shared utilities
   - naming patterns
   - current business rules

3. Historical context
   - similar stories
   - prior decisions
   - learnings
   - known exceptions

4. Delivery context
   - board status
   - linked epic
   - notification channel
   - owner
   - priority

Rule:
- business story content must remain business-first
- technical findings belong in impact analysis or implementation notes
